Feedback & progress

Alerts, toasts, and the two states this product cannot get wrong: the blocking evaluation wait, and the undo window on a permanent action.

Evaluation in progress

Evaluation runs inside the request that submits the claim, so the developer's own tab is held open for its full duration. That makes this a full-attention state, not a background toast — and it is why total work is capped by the platform's execution ceiling. The bar is indeterminate on purpose: there is no honest percentage for an LLM evaluation, and inventing one would be a lie the user could later catch.

Past 70% of the execution ceiling the elapsed clock turns amber. The developer is holding an open request and deserves warning before it is cut off, not after.

Undo window

Repo attachment is permanent once this expires — there is no detach endpoint and no soft-delete state. So the countdown is not decoration: it is the entire window in which the action is reversible, and the time remaining has to be legible at a glance rather than inferred from a fading toast.

Alerts

Note the tone split again: a negative verdict is not an error, and an infrastructure failure is not a verdict. They never share a hue — coral for things that genuinely failed, periwinkle for a result that happens to be negative, amber only for attention.

Reports are visible to stakeholders immediately
There is no approval or release step. As soon as an evaluation completes, its report is visible to everyone on the project.
